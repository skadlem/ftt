You are planning a software project for an IoT fleet dashboard focused on electric delivery vans. Context: a logistics company operates 450 EVs across three depots. Telemetry arrives via MQTT into an existing time-series database, including SOC, battery temperature, charge session events, GPS, odometer, and fault codes. Operations currently uses ad hoc Grafana panels and spreadsheets, which do not show charging readiness or battery degradation trends. Goal: plan a dashboard product that helps dispatch and maintenance teams monitor vehicle state, identify charging blockers, forecast usable range for next routes, and prioritize battery service. Constraints: web app must support role-based views for dispatchers, depot managers, and maintenance; refresh vehicle cards at least every 60 seconds; historical views must retain 24 months; offline depot links should not break ingestion; solution must use existing PostgreSQL and Timescale data stores, not introduce a third-party BI subscription; UI should handle low-bandwidth depot networks; alerts must be deduplicated and explain why triggered. What exists: device identity registry, MQTT broker, ingestion workers, schema for raw telemetry, simple Grafana panels, and a REST API for route assignments. Deliver a plan covering milestones, data model additions, API endpoints, alert rules, UX modules, validation approach, and rollout to one depot before fleet-wide release.
