You are planning an IoT fleet dashboard for a food distribution company that operates refrigerated trailers and last-mile chilled vans. Context: sensors report compartment temperature, door open/close, compressor status, humidity, battery voltage, and GPS every 30 seconds through a cellular gateway. The company must prove HACCP compliance to retailers and respond quickly to excursions. Existing stack includes AWS IoT Core, S3 raw event archive, a rules engine that emits alarms, and a basic status page showing current temperature only. Goal: define a project to build a compliance-focused dashboard with live fleet map, excursion investigation timeline, sensor calibration records, and exportable custody reports. Constraints: data must be immutable once signed for audit; dashboards must separate carrier, warehouse, and QA roles; alarm severity must account for product type and elapsed time outside threshold; reports must cover trips, not just calendar days; mobile responsiveness is required for drivers using phones at dock doors; do not store raw telemetry in the app database if it duplicates S3, but provide query acceleration for 7 days. What exists: device certificates, trip manifest API, temperature threshold configuration table, alarm notification Lambda, and a customer logo requirement. Produce a phased plan including data retention, audit trail, report generation, UX flows, edge cases like sensor dropout and door-open allowances, and acceptance tests with simulated excursion data.
