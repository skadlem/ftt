You are planning a software project for an IoT fleet dashboard used by a construction equipment rental company. Context: 1,200 assets such as generators, compressors, light towers, and skid steers carry telematics boxes reporting engine hours, fuel level, hydraulic temperature, fault codes, geofence entry/exit, and idle time over LoRa and cellular. The business loses margin when assets sit idle, are misused, or miss maintenance windows. Today there is a device inventory table, a REST API for customer reservations, a Kafka topic for raw events, and an internal admin screen that lists last known location. Goal: create a plan for a dashboard that gives branch managers live utilization, maintenance supervisors health-based work orders, and finance estimated usage billing. Constraints: the system must tolerate intermittent connectivity and late-arriving events without corrupting utilization metrics; geofences are customer-defined and versioned; maintenance thresholds vary by model and lease contract; dashboard must not expose one customer's assets to another; support CSV export and webhook notifications; keep operational latency under 5 seconds for live location; use existing React frontend and Kafka/ClickHouse analytics stack. What exists: asset registry, geofence CRUD, fault code dictionary, reservation calendar, and a prototype map widget. Deliver a roadmap with event deduplication, derived metrics, work order integration, tenancy model, permission matrix, data quality monitoring, and pilot criteria for two branches.
